Methodology

From the labeled dataset to the web prediction.

01 · DATA COLLECTION

Load the Kaggle CSV with 9,537 labeled session rows and nine candidate fields.

02 · PREPROCESSING

Exclude the session ID; median-impute and scale numeric fields; mode-impute and one-hot encode categories.

03 · TRAIN & SELECT

Use a stratified 80/20 split. Compare Random Forest, Logistic Regression, Decision Tree, and SVM with 3-fold cross-validation; use recall-weighted F2 to select the primary model.

04 · TEST & INTEGRATE

Report holdout accuracy, precision, recall, F1 and confusion matrix. Load the saved preprocessing-and-model pipeline in Flask.

How to read these results

Metrics are measured on the held-out portion of this Kaggle dataset. The dataset is tagged synthetic, so these scores do not establish performance on live or real-world network traffic. The model is a research prototype, not an operational intrusion prevention system.

COMPUTER ENGINEERING

Program alignment

SAFE Flow applies Computer Engineering concepts in computer networks, cybersecurity, data processing, and web application development.

Problem statement

Small schools and offices may not have dedicated security staff to review suspicious network sessions and login patterns.

How AI supports the work

A trained supervised classifier evaluates nine session-level fields and provides a normal or attack screening result with a short sensitivity summary.

Target users

Small institutions without a dedicated security team, plus Computer Engineering students and educators studying applied intrusion detection. Results support review; they do not replace a security system or automatically block activity.

Project scope

This research prototype analyzes submitted session records only. It does not capture packets, monitor live network traffic, block attacks, or replace a dedicated security system.
